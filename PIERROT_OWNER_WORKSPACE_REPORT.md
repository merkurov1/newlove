# PIERROT OWNER — iPad-first workspace

Отчёт по реализации и короткая инструкция по работе с приложением.

- Репозиторий: `merkurov1/newlove`
- Ветка: `main`
- Коммиты: `4658426a`, `567bbcfd`, `8b3cc75e`, `ecec6c9f`
- Рабочий адрес: `https://www.merkurov.love/admin/pierrot`
- Отдельный Dev-раздел не создавался.

---

## 1. Как открыть и установить

### На iPad / iPhone

1. Откройте `https://www.merkurov.love/admin/pierrot` в Safari.
2. Войдите в аккаунт с ролью `ADMIN`.
3. Нажмите «Поделиться» → «На экран Домой».
4. Название приложения будет `Pierrot`.
5. Запускайте его с Home Screen как отдельное standalone-приложение.

У приложения собственный manifest:

- `start_url`: `/admin/pierrot`
- `scope`: `/admin/pierrot`
- `display`: `standalone`
- `theme_color` / `background_color`: `#F8F6F1`

Корневой manifest публичного сайта не заменялся.

### На desktop

Откройте тот же адрес в браузере. Доступна та же раскладка: рейка слева, центральная колонка, панель диалогов и инспектор источников.

## 2. Навигация

Левая рейка шириной 88px:

- CHAT
- FLOW
- BRAIN
- DASH

Экран SETTINGS убран из PWA-меню. Аккаунт и подключения остаются доступны через существующие разделы админки.

На ширине меньше 700px рейка превращается в нижний tab bar с учётом safe-area.

### Горячие клавиши

- `⌘/Ctrl + 1` — CHAT
- `⌘/Ctrl + 2` — FLOW
- `⌘/Ctrl + 3` — BRAIN
- `⌘/Ctrl + 4` — DASH
- `⌘/Ctrl + N` — новый диалог

Сочетания не перехватываются, когда курсор находится в `input`, `textarea`, `select` или `contenteditable`.

## 3. CHAT

### Пустой диалог

Показывается обзор состояния:

- «Всё спокойно.»
- короткое саммари;
- короткий коммерческий отчёт: «Да, разбогатели» / «Нет, тише прошлого периода» / «Пока без продаж»;
- сумма подтверждённых оплат и число новых подписок Flow;
- пять строк: Пользователи, Подписчики, Flow, Диалоги, Медиа;
- состояние и точка:
  - залитая чёрная — рост;
  - охра — внимание;
  - полая серая — нейтрально;
  - пунктирная — нет данных.

Состояния строго ограничены словарём:

`растёт`, `стоит`, `падает`, `тихо`, `пухнет`, `тревога`.

Состояние рассчитывается кодом, а не моделью. Сравнение идёт с предыдущим равным периодом.

Коммерческий отчёт считает только подтверждённые покупки, пожертвования и подтверждённые подписки Flow. Checkout, интерес и показанные предложения не считаются выручкой. GBP и USD не суммируются; возвраты и комиссии Stripe не вычитаются.

### Аватар и ответы

В шапке чата и у ответов используется оригинальный аватар Пьеро из прежнего дизайна. Он self-hosted:

`/pierrot/pierrot-avatar-512.jpg`

Ответы оформлены редакционно: аватар, имя, провайдер, крупный serif-текст, источники и компактная строка оценки.

### Диалоги

- Кнопка `PanelLeft` в шапке чата открывает/закрывает список диалогов.
- Нажатие на активный CHAT в рейке тоже переключает список.
- «Новый диалог» очищает текущую беседу.
- Сохранённые owner-диалоги открываются из списка.
- Для сохранения истории нужно явно разрешить сохранение в строке под composer: «Разрешить сохранение».

Правила consent не менялись. Если сохранение выключено, ответ приходит, но диалог не сохраняется.

### Отправка сообщений

- `Enter` — отправить.
- `Shift + Enter` — новая строка.
- Backend не поддерживает streaming, поэтому интерфейс честно показывает состояние «Pierrot формулирует ответ», а не имитирует поток токенов.

### Источники

Если retrieval реально вернул источники, под ответом появляется:

`из базы · N источников ›`

Нажатие открывает правый инспектор шириной 300px:

- тип источника;
- название;
- домен / автор;
- дата;
- фрагмент;
- ссылка, если backend её вернул;
- состояние retrieval и код ошибки, если он есть.

Если источников нет, строка не показывается. Поисковые запросы не придумываются.

### Действия с сообщением

Кнопка `···` у ответа открывает:

- «В Brain»;
- «Во Flow».

Это только handoff: текст переносится в соответствующий экран, но ничего не сохраняется и не публикуется автоматически.

Под ответом также есть оценка «Ответ полезен? Да / Нет». Она пишется в существующий `/api/pierrot/events` как `answer_feedback` и связывается с server assistant message id. Оценка доступна только при включённом сохранении; иначе кнопки отключены.

## 4. BRAIN

Экран «Что добавить в мозг?».

Поддерживается:

- ссылка;
- обычный текст;
- PDF;
- TXT.

Сценарий:

1. Выберите тип.
2. Вставьте ссылку/текст или выберите файл.
3. Нажмите «Проверить ссылку» / «Проверить текст» / «Загрузить и проверить».
4. Проверьте preview: заголовок, автор, дата, язык, chunks, warnings, duplicate.
5. При необходимости измените предложенную метку.
6. Нажмите «Сохранить».

Используются существующие endpoints:

- `/api/admin/brain/uploads`
- `/api/admin/brain/preview`
- `/api/admin/brain/sources`
- `/api/admin/brain/worker`

Файлы уходят напрямую в приватное хранилище через signed upload, а не через JSON.

### Ограничения

- **Фото**: можно выбрать и посмотреть локально, но Brain ingestion не принимает изображения. Интерфейс это прямо сообщает.
- **Голос**: можно записать локально, но backend-транскрибации нет. Аудио не попадает в Brain.

Ниже показаны пять последних добавлений: название, тип, дата, статус обработки и код ошибки, если он есть.

## 5. FLOW

Экран Flow открывается в стиле публичной страницы `/flow`:

- белый фон;
- серифная типографика;
- заголовок `Flow`;
- ссылки Bluesky / Telegram / RSS;
- лента опубликованных записей;
- composer «Что нового?»;
- кнопка «Опубликовать».

Нажатие на composer открывает тот же `NewPostModal`, что и на сайте. Это значит, что доступны:

- текст;
- вставка ссылки;
- YouTube-preview;
- загрузка изображения;
- удаление вложений;
- публикация и редактирование через существующие `/api/flow/items`.

Публикация идёт напрямую через существующий Flow lifecycle, без отдельного PWA-превью и без дублирующих настроек.

В ленте доступны:

- «Редактировать»;
- «Удалить» с подтверждением;
- «Открыть на сайте».

Черновики и отдельное 10-секундное окно отмены убраны: PWA теперь работает так же прозрачно, как публичная страница и её модалка.

## 6. DASH

Компактный дашборд, который помещается на iPad landscape и остаётся информативным.

Верхний ряд — пять показателей:

1. Пользователи
2. Подписчики
3. Flow
4. Диалоги
5. Медиа

Для каждого:

- реальное число;
- состояние из фиксированного словаря;
- SVG sparkline;
- изменение за период и предыдущее значение.

Ниже:

- коммерческий вердикт: разбогатели или нет;
- сумма подтверждённых оплат;
- Heart & Angel, UNFRAMED, Temple Tributes, Flow;
- checkout starts и abandonment rate;
- честная пометка о неполных источниках.

Нижний блок — три колонки:

**Pierrot**
- диалоги сегодня;
- диалоги за период;
- сообщения;
- средняя длина;
- вернувшиеся;
- retrieval failure rate;
- негативный feedback;
- средняя задержка ответа.

**Brain**
- документы;
- чанки;
- доля векторов;
- очереди Brain / Graph / Media;
- поиск за 30 дней;
- доля найденных результатов.

**Media**
- записи;
- записи с текстом;
- цитаты;
- темы;
- сущности;
- связи.

Все цифры берутся из существующих таблиц, views и analytics-функций. Отсутствующие данные показываются как «—» или «недоступно», а не как ноль.

## 7. SETTINGS

Экран удалён из PWA-меню и маршрута. Настройки аккаунта и интеграций остаются в существующей админке.

## 8. Offline

Service worker кэширует только:

- публичный offline shell;
- manifest;
- иконки;
- hashed-ресурсы `/_next/static/`.

Service worker **не кэширует**:

- `/api/*`;
- `/api/pierrot-web`;
- `/api/admin/*`;
- приватные Brain-ответы;
- owner-статистику;
- настройки;
- авторизационные ответы;
- авторизованный HTML `/admin/pierrot`.

При отсутствии сети:

- открывается offline-страница;
- отправка сообщений, Brain, Flow, Settings и публикация отключены;
- интерфейс не делает вид, что операция выполнена.

Push-уведомления не добавлялись.

## 10. Реализовано / ограничено

### Работает через существующий backend

- owner-чат и consent;
- восстановление сохранённых диалогов;
- источники ответа;
- Brain upload/preview/enqueue/worker;
- Flow draft/publish/crosspost/delete;
- DASH на существующих таблицах, observatory и Brain/Media analytics views;
- коммерческий отчёт из существующих commercial views;
- оценка ответов через существующий `/api/pierrot/events`;
- Flow composer и публикация через существующую модалку сайта;
- PWA manifest, iOS metadata, service worker.

### Честные ограничения

- нет streaming;
- фото и голос не индексируются Brain;
- GitHub OAuth отсутствует;
- нет выбора отдельных каналов при публикации;
- редактирование опубликованного Flow не обновляет внешние копии;
- реальные внешние публикации в тестах не выполнялись.

### Что нужно добавить вручную

1. Self-hosted **Newsreader 400/500** WOFF2.
2. Self-hosted **IBM Plex Mono 400** WOFF2.
3. Финальные ассеты маски Пьеро / квадратного логотипа:
   - 180×180;
   - 192×192;
   - 512×512;
   - maskable.

Сейчас используются:

- локальный serif/mono fallback без Google Fonts;
- оригинальный аватар Пьеро, self-hosted в `public/pierrot/pierrot-avatar-512.jpg`;
- промежуточный типографический знак `P` для PWA-иконки.

## 12. Быстрый сценарий на каждый день

1. Открыть Pierrot с Home Screen.
2. Посмотреть коммерческий вердикт и пять состояний на CHAT.
3. Открыть DASH для полной картины по проекту.
4. Открыть диалог из списка или начать новый.
5. Задать вопрос; при необходимости открыть «из базы · N источников» и оценить ответ.
6. Нужный ответ отправить в Brain или Flow через `···`.
7. В Brain проверить preview и сохранить.
8. В Flow открыть «Что нового?», написать пост, вставить ссылку/фото и опубликовать через ту же модалку, что на сайте.
