# Media Archive — систематическая сверка раннего периода (2000–2026)

Дата: 2026-11-22  
Задача: `ad529408-6fb0-424a-b701-fe1a26fb9331`  
Режим: read-only исследование + локальное пополнение `data/media.ts`.  
Production Supabase в этом окружении недоступен: нет `.env.local`, service-role
ключа и разрешённого доступа к management API. Поэтому импорт в
`media_archive_records` и постановка в Brain queue **подготовлены, но не
выполнены**. Это единственное существенное ограничение; оно вынесено в
`unverified` в конце.

## 2. Метод

1. Сначала собран список уже известных записей: `data/media.ts`,
   `docs/audits/media-rag-reconciliation-inventory.csv` (223 строки,
   2026-10-30), `data/media-audit/current-baseline.json` (265 записей,
   2026-11-05) и заявленная владельцем статистика 328/86.
2. Поиск шёл по именам и транслитерациям:
   `"Антон Меркуров"`, `"Anton Merkurov"`, `"Merkurov"`, `"А. Меркуров"`,
   `Merkurov Anton`, `Anton Merkuroff`, `Anton Merkurov e-gold`,
   `Меркуров HYIP`, `Меркуров электронные деньги`.
3. Для каждого кандидата проверялись: заголовок, дата, издание, язык, роль,
   прямой URL и canonical URL. Материал без подтверждённой даты/URL в базу не
   попадал.
4. Для мёртвых/переехавших страниц использовался Internet Archive CDX и
   сохранённые снимки (`web.archive.org`). Для живых — первоисточник.
5. Дубли определялись по canonical URL, raw URL и по комбинации
   `title + outlet + published_date`. Однофамильцы и сомнительные совпадения
   вынесены в `doubtful`, а не в публичный архив.
6. Поисковые движки: Brave Search и Yahoo/Bing как резерв. Google, Yandex,
   DuckDuckGo, Mojeek, Startpage и Muck Rack отдали captcha/403/пустую
   выдачу; это зафиксировано, а не замаскировано.

## 8. Импорт и Brain ingestion

### 8.1. Импорт библиографии

Добавлен отдельный точечный импортёр:
`scripts/media-audit/import-early-period.ts`. Он читает только 34 URL из
манифеста (а не весь локальный fallback), нормализует canonical URL, читает
существующие `canonical_url` из `media_archive_records` и вставляет только
отсутствующие.

```bash
# dry-run: 34 кандидата, ничего не пишет
pnpm media:import-early

# применить: вставить только отсутствующие canonical URL
pnpm media:import-early --apply
```

Ожидаемый результат: `inserted` — от 32 до 34 (две записи 2009 года могут уже
быть в production), `alreadyPresent` — остальное. Скрипт не меняет
`data/media.ts` и не печатает секреты.

### 8.2. Brain ingestion

После импорта библиографии:

```bash
# dry-run: покажет link/create/enqueue план, ничего не меняя
npx tsx scripts/knowledge/reconcile-media-rag.ts

# применить: создать knowledge_documents и поставить coverage jobs
npx tsx scripts/knowledge/reconcile-media-rag.ts --apply
```

`enqueueMediaCoverageJob` сначала вызывает `findActiveMediaJob` и возвращает
`already_queued`, если по записи уже есть `queued`/`processing` job. Поэтому
повторный запуск не создаёт дубли. Для `radio` и `video` (`Эхо`, Теплица)
`reconcile-media-rag` намеренно не создаёт full-text документ: это
метаданные/эфир, а не статья. Остальные 32 кандидата — текстовые.

Проверка отсутствия дублей jobs — SQL 8b/8c/8d в
`docs/audits/media-early-period-verification-2026-11-22.sql`.

   их судьба решается SQL-проверкой и решением владельца.

   ссылки в записях сохранены как канонические первоисточники.
